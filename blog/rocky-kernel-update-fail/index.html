Rocky Linux: Kernel Update Is Not Applied

CVE-2026-98432 kernel: ipv4: free inet_opt and ireq_opt after an RCU grace period

While working on the response to this vulnerability, I encountered a Rocky Linux system where the kernel was not updated.

Environment

OS: Rocky Linux 9.8

Actually, this host (KVM guest) was upgraded from Rocky Linux 8 to Rocky Linux 9.

Procedure

I expected that the system could be updated normally with the following command, but...

sudo dnf update
Last metadata expiration check: 1:01:11 ago on Thu Nov  5 14:16:11 2026.
Dependencies resolved.
Nothing to do.
Complete!

Nothing to do. Update completed.

I also checked with rpm -qa, but nothing was displayed.

Note: Other packages could be found.

rpm -qa | grep kernel

I tried again, this time specifying kernel.

sudo dnf update kernel
Last metadata expiration check: 1:00:30 ago on Thu Nov  5 14:16:11 2026.
Package kernel available, but not installed.
No match for argument: kernel
Error: No packages marked for upgrade.

The kernel package is available, but it is not installed.

No match for argument: kernel

Error: No packages marked for upgrade.

What does it mean that the kernel package itself is not installed?

Conclusion

It seems that the kernel package had somehow disappeared.

I don't know why.

I investigated this (described later), but could not find the reason in the end. Something may have happened due to the migration from Rocky Linux 8 to Rocky Linux 9, or some other related operation.

Since the package was no longer installed, it was not updated by dnf update.

For now, I have no choice but to install the package. However, if I simply run dnf install kernel, the latest version will be installed. In that case, I cannot fully verify whether a subsequent dnf update will work correctly.

Therefore, I decided to do the following:

  • Intentionally install an older version of the kernel.
  • After confirming that it has been installed, run dnf update and check whether it is updated.

I checked ftp.riken.jp and decided to install the oldest version available.

Note: Packages other than kernel are required as dependencies.

Note: Another way would be to run dnf install kernel-0:5.14.0-687.12.1.el9_8.x86_64, based on the result of the previously mentioned dnf repoquery --available --show-duplicates kernel. However, I deliberately chose the more tedious method. lol

wget https://ftp.riken.jp/Linux/rocky/9/BaseOS/x86_64/os/Packages/k/kernel-5.14.0-687.12.1.el9_8.x86_64.rpm
wget https://ftp.riken.jp/Linux/rocky/9/BaseOS/x86_64/os/Packages/k/kernel-modules-5.14.0-687.12.1.el9_8.x86_64.rpm
