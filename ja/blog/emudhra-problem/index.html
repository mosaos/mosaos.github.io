eMudhra ( イームドラ ) 証明書問題とは

PHP の脆弱性問題が同時期に発表されたせいか、私の周囲ではいまいち取り上げられ方が微妙な感もあるのですが、2026/10/20 に証明書関連でかなりヤバい問題が発覚しました。

eMudhra Intermediate CA Compromise

eMudhra の問題をざっくり説明すると、

  • 「本物のウェブサイトやアプリであること」を証明するSSL証明書の作成において、設定ミスがあった。
  • 本来、十分な乱数を使って生成すべき秘密鍵が、設定ミスによって 4 や 56 のような極端に小さい値になっていた。
  • そのため、公開されている証明書から対応する秘密鍵を容易に復元できる状態になっていた。

ってやつです。

どうすればよい？

問題の証明書は信頼しないようにプログラム(webブラウザ、各種SSLを使った通信を行うプログラムの更新が必要になった。

Web ブラウザ ( Chrome や Firefox など )

ブラウザベンダーは、アプリ本体のアップデートを待たずに、CRLSet や OneCRL などの仕組みを使って、問題のある中間 CA 証明書をブロックしました。

確認方法

Does your client still trust the compromised intermediates? にアクセスして、リストされている Intermediate CA の結果 ( Result ) が全て ✅ Did not connect になる事を確認する。 ならない場合には、web ブラウザのアップデートをしてから再度確認してください。

※ ✅ Did not connect にならない状態で利用を続けると悪意のある攻撃者サイトを本物と誤認してセキュリティ被害にあう可能性がある。問題が解消するまで利用は止めるべき。

ブラウザ以外のプログラム

Web ブラウザ以外にも証明書を利用して接続を行うものはたくさんあります ( Java, Python, Go, curl、Linux OS等 )。

Web ブラウザ以外のプログラムでは、ブラウザのように共通の仕組みでブラックリストが配信・適用されるとは限りません。OS の証明書ストアを利用するものもあれば、プログラム独自の証明書ストアを使用するものもあります。そのため、各プログラムや実行環境に応じた対策と確認が必要です。

一般ユーザーの場合には問題は限定的かもしれませんが、IT部門やシステム担当、インフラ担当者にとっては、様々なシステムをアップデートする必要があります。

curl の場合

とりあえずみんな大好き curl で試してみた結果を乗せる。

※ Who has patched? にパッチがあるプログラムやOSがリストされているので、個別はこれらを参照すると良い。

先ずは Does your client still trust the compromised intermediates? にあった一つに対して curl を実行してみた。

$ curl https://dv-g3b-emudhra.we-have-a-problem.com/
Your client successfully connected to the site. That's bad!

That's bad!

パッケージ更新で対応可能か試す。

$ sudo dnf update -y

更新後に再実行する。

$ curl https://dv-g3b-emudhra.we-have-a-problem.com/
Your client successfully connected to the site. That's bad!

駄目だった。

ブラックリストに登録する。

vi /etc/pki/ca-trust/source/blacklist/emudhra-g3b.pem

上で取得された真ん中の証明書の内容 ( -----BEGIN CERTIFICATE----- ～ -----END CERTIFICATE----- ) を保存する。

以下のようにしてもよい。

cat > /etc/pki/ca-trust/source/blacklist/emudhra-g3b.pem <<'EOF'
-----BEGIN CERTIFICATE-----
MIIDaDCCAu6gAwIBAgIQAKSu5njyM2K0wORgt3LyFDAKBggqhkjOPQQDAzBWMQsw
...
gt2TlfJbHii+KNvK
-----END CERTIFICATE-----
EOF

ブラックリストを登録したら反映させる。

sudo update-ca-trust
sudo trust extract-compat

ブラックリストされてるか確認。
trust: blacklisted になってる。

$ trust list | grep -A5 -B5 "EM DV TLS CA - G3B"
pkcs11:id=%E2%1E%2F%E7%1C%19%39%0E%55%4B%62%C1%20%24%57%35%24%8A%25%14;type=cert
    type: certificate
    label: EM DV TLS CA - G3B
    trust: blacklisted
    category: authority

pkcs11:id=%42%3D%2B%24%A6%C1%45%CE;type=cert
    type: certificate

再実行する。

$ curl https://dv-g3b-emudhra.we-have-a-problem.com/

どうやら blacklist 登録自体は成功している。

trust list では EM DV TLS CA - G3B が trust: blacklisted となり、wget でも証明書エラーとなった。

一方で curl および openssl s_client は引き続き証明書を 有効と判定しているようだ。
