パトラッシュ、僕はもう疲れたよ

先日の PHP2shell
私の周りでは、PHP が古くてすぐに対応ができない等の理由から、

一旦サイトを閉鎖する！

とか言ってたところもありました。

動的 CMS は便利ですし、WordPress は特にシェアも高く、特に日本ではどこもかしこも WordPress みたいな感じもありますが、　　

あなたのサイトに動的 CMS は必要でしょうか？

上記脆弱性に限らず CMS 自体やプラグイン管理、定期的なアップデートなど、Web サイトを安全に運用したいといった場合、メンテナンスコストはバカになりません。

会社案内、製品紹介、ブログ、技術情報の公開など、コンテンツを閲覧してもらうことが主な目的のサイトに、本当に動的な仕組みが必要でしょうか？

そういう私もかつては joomla や drupal, wordpress 等を利用してサイトを管理していたりするのですが、昨今の情報漏洩、セキュリティリスクの高まり等を見るにつけ、単なるコンテンツ配信したいだけなら「めんどくさすぎる！」という感じがしています。
本来の目的のコンテンツの作成・配信に注力して、管理コストは出来る限り減らしたい！というのが多くの人の感じるところではないでしょうか。

こういったコストを削減したい場合に、SSG (Static Site Generator) と呼ばれる静的 CMS を利用する事が可能です。

SSG を使えば、コンテンツから HTML などの静的ファイルを事前に生成し、公開サーバーではそれらを配信するだけの構成にできます。

以下では、SSG　を採用するメリットと、実際に Zola を使って構築したサイトを例に紹介します。

※ 「私は WordPress に慣れてるの！」「私は WordPress が使いたいの！」 といった向きには全く響かない可能性もありますが。。

動的？静的？

SSG？静的 CMS？という方もいるかもしれないので、軽く説明しておきましょう。

動的 CMS

「コンテンツ ( 文章や画像など ) をデータベース ( DB ) などに保存しておき、ユーザーがアクセスするたびに、システムがそれらのコンテンツをテンプレートなどと組み合わせて、動的に Webページを生成・表示する仕組み」 です。
WordPress, Drupal 等多くの CMS が該当します。

静的 CMS (SSG)

動的 CMS に対して、静的 CMS というものもあります。
これは、「あらかじめ HTML などの静的ファイルを生成しておき、ユーザーがアクセスした際には、生成済みのファイルをそのまま配信・表示する仕組み」です。
今回紹介する Zola も静的 CMS の一つです。

比較

簡単な比較項目を以下に示します。
以下以外にも比較項目は様々ありますが、まずはざっくりと理解するためのものに絞りました。

項目動的CMS ( WordPress )SSG ( Zola )
セキュリティリスクCMS、PHP、DB、プラグインなど、攻撃対象が多い静的ファイル配信が中心で、攻撃対象を大幅に削減できる
脆弱性対応本体・プラグイン・テーマなどの継続的な更新が必要公開サイト側のサーバーサイドプログラムがなく、管理対象が少ない
プラグイン管理プラグインごとの脆弱性・更新状況・互換性の確認が必要WordPressのようなサーバーサイドプラグイン管理は不要
公開サイトの攻撃対象PHPやDBなどを狙った攻撃への対策が必要サーバーサイドの実行環境がないため、攻撃対象を限定できる

動的 CMS でないと難しい事

「SSG いいじゃん！」 と思うかもしれませんが、動的 CMS でないと実現が難しいこともあります。

例えば、次のようなサイトを考えてみましょう。

  • 会社概要
  • サービス紹介
  • 技術ブログ
  • 開発実績
  • 社内ナレッジ
  • FAQ
  • マニュアル
  • お知らせ

これらは基本的に、あらかじめ作成したコンテンツを利用者に公開するサイトです。 アクセスするたびに PHP 等で処理したり、DB からコンテンツを取得したりする必要はありません。

一方、次のような機能は動的 CMS でないと難しいものになります ( SSG だけでは実現できない可能性が高い )。

  • ブラウザ上で誰でも簡単に記事を編集・投稿できる
  • 複数の編集者による承認ワークフローが必要
  • 会員登録やログインが必要
  • ユーザーごとに異なるコンテンツを表示する
  • ユーザー投稿やコメントを管理する
  • ECや決済などの業務機能を提供する

どちらを採用すべきか？

上では 動的 CMS でないと難しい事を示しましたが、これらを踏まえると、 動的 CMS と SSG での お奨めの棲み分け は以下のようになります。

サイトの用途推奨
企業・組織の情報発信サイトSSG
技術ブログ・ナレッジベースSSG
製品紹介・サービス紹介SSG
ポートフォリオSSG
マニュアル・技術ドキュメントSSG
社内情報共有ポータル要件次第
多数の非エンジニアが記事を投稿するサイト動的CMS
会員制サイト動的CMS
ECサイト動的CMS
ユーザーごとに表示内容が異なるサイト動的CMS
ユーザー投稿・コメントが中心のサイト動的CMS
  • 公開するコンテンツが主体
  • 記事の作成・更新頻度がそれほど高くない
  • Git などによるコンテンツ管理が可能
  • セキュリティリスクと保守負担を減らしたい

といったサイトでは SSG を採用する事で、管理コストやセキュリティリスクを削減できます。

WordPress を利用していてその利便性を感じて使っている方も多いと思いますが、

「WordPressで実現できること」と「WordPressでなければ実現できないこと」は違います。

昨今のセキュリティ事情を考えた場合、よりセキュアに運用できる/メンテナンスコストも低い 状態を実現するために、一部を SSG に置き換える判断をしてもよいのではないでしょうか。

Zola

今回紹介する Zola は、Rust 製の SSG (Static Site Generator) です。

Markdown などで作成したコンテンツを、テンプレートと組み合わせて HTML などの静的ファイルに変換します。

特徴としては、

  • Rust 製で、ビルドが高速
  • Markdown によるコンテンツ管理
  • 多言語サイトに対応
  • タグやカテゴリーなどの分類機能
  • テンプレートによる柔軟なデザイン変更
  • 検索用インデックスの生成
  • Node.js や npm などに依存しないシンプルなビルド環境

といったものがあります。

WordPress のような管理画面やプラグインによる拡張を前提とせず、コンテンツとデザインを分離して管理できるのも特徴です。

もちろん、WordPress のようにブラウザ上ですべてを編集できるわけではありませんが、ブログや技術情報、ポートフォリオなどのコンテンツ配信を目的とするサイトであれば、十分実用的な選択肢になります。

どんなサイトに向いている？

例えば、企業の情報発信サイト、製品・サービス紹介、技術ブログ、個人のポートフォリオなど、コンテンツを閲覧してもらうことが主な目的のサイトであれば、Zola で十分実用的なサイトを構築できます。

上述の通り、このサイトが Zola と daisyUI を使った実例になっています。

公開・運用について

SSG のメリットは、サイトの構築だけでなく、公開・運用の手軽さにもあります。

例えば、以下のような構成が可能です。

  • GitHub Pages
    GitHub と GitHub Actions を利用して無料で公開
  • 独自ドメイン
    GitHub Pages でも独自ドメインを利用可能
  • Cloudflare Pages
    こちらを利用して公開することも可能

当サイトも GitHub Pages を利用して無料で運用しています。

また、問い合わせフォームなどが必要な場合も、Google Forms などの外部サービスを利用したり、SNS の DM で受け付けたりすることで十分なケースも多いと思います。

すべてを CMS 側に持たせる必要はありません。

必要な機能だけを外部サービスと組み合わせることで、シンプルな構成で運用することができます。

興味を持たれた方は一度実際に試してみてはいかがでしょうか。
